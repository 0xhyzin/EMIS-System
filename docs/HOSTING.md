# الاستضافة وحالة تشغيل الموقع

## إصلاح خطأ Vercel

كان إعداد Vercel يحمّل `server.js` مباشرة، مع أن الملف يصدّر `createApp` فقط، ويبدأ الاستماع عند تشغيله بالأمر `npm start`. سجل Vercel للطلب `m48g9-1791572044126-544fd7076f3b` أظهر:

```text
Invalid export found in module "/var/task/server.js".
The default export must be a function or server.
```

أصبح المدخل `vercel-entry.js` دالة طلبات افتراضية متوافقة مع Vercel. لا يستورد خادم الكمبيوتر ولا ينشئ SQLite أو جلسات في تخزين مؤقت.

## قبل توصيل الخادم الدائم

- الصفحة الرئيسية تعرض «الموقع في مرحلة تجهيز الاستضافة».
- `GET /api/deployment/status` يعرض `ready: false` ورقم الإصدار.
- واجهات البرنامج تعيد 503 مع رسالة عربية، ولا تحفظ بيانات أو تسجل دخولًا وهميًا.
- ملفات البيانات والجلسات والمخرجات المحلية مستبعدة من رفع GitHub وVercel.

هذه حالة تجهيز، وليست النسخة الكاملة العاملة. التشغيل المحلي بواسطة `npm start` مستمر كالمعتاد.

## ما يحتاجه التشغيل والكمبيوتر مغلق

يلزم خادم مستقل يعمل باستمرار، مع مجلد دائم لـ `DATA_DIR`، وNode.js 22.13 أو أحدث، وLibreOffice للتصدير إلى PDF، ومتصفح منفصل محمي للربط الفعلي بالوزارة. يلزم أيضًا دخول آمن للمالك بدل الاعتماد على صلاحية الكمبيوتر المحلي. لا يكفي رفع ملفات البرنامج إلى Vercel، لأن SQLite المحلي لا يُحفظ فيه بشكل دائم.

لم يُجهز خادم دائم أو تُنقل إليه بيانات المدرسة بعد. أي خدمة مجانية تعتمد على شروطها وتوافر مواردها؛ لا تستخدم خطة تجريبية مدفوعة باعتبارها استضافة مجانية دائمة.

## بوابة Vercel عند تجهيز الخادم

البوابة تدعم تمرير الطلبات إلى أصل HTTPS محدد بواسطة `EMIS_BACKEND_ORIGIN`، مع سر مستقل في `EMIS_PROXY_SECRET`. لا يوضع السر في الكود أو المتصفح. تحفظ البوابة عنوان الموقع العام في Host وتضيف عنوان المصدر والبروتوكول صراحة، وتزيل سر الزائر إن أرسله.

هذه المتغيرات وحدها لا تجعل خادم الكمبيوتر جاهزًا للإنترنت. قبل تفعيلها، يجب تعديل الخادم الدائم ليتحقق من السر بمقارنة آمنة، ويثق في رؤوس البوابة بعد التحقق فقط، ويستخدم `APP_ORIGIN` العام، ويتيح صلاحيات المالك بتسجيل دخول مستقل. الخادم المحلي الحالي يرفض الرؤوس المُمررة ولا يمنح المتصل البعيد صلاحية المالك.

بعد ذلك اختبر الدخول وحفظ الجلسة والإضافة والتعديل والحذف والمزامنة والتصدير بالصيغ الثلاث بعد إعادة تشغيل الخادم. أنشئ نسخة احتياطية للبيانات قبل نقلها، ولا تنقل ملف SQLite أثناء عمل البرنامج دون طريقة نسخ احتياطي تدعم SQLite.

مراجع الإعداد: [دالة Node.js على Vercel](https://vercel.com/docs/functions/runtimes/node-js)، [SQLite على Vercel](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel).
